# 0.4 generator architecture

AsyncEventBridge 0.4 consolidates the modern Roslyn generators around one discovery, classification, modeling, and emission pipeline. The goal is to make support for a new event shape a single architectural change instead of three independent generator changes.

## Pipeline

```text
Roslyn symbols / generation targets
              |
              v
   GeneratorSymbolAnalysis
   - inherited event discovery
   - hidden-member handling
   - accessibility
   - valid generation targets
              |
              v
     EventShapeClassifier
   - standard EventHandler
   - EventHandler<TPayload>
   - strongly typed/custom delegates
   - async-lifetime compatibility
              |
              v
    EventGenerationModel
   - event symbol
   - normalized shape
   - handler type
   - sender type
   - payload type
   - generated accessibility
              |
      +-------+--------+
      |       |        |
      v       v        v
 EventWait  EventStream  EventOccurrence
  Emitter     Emitter       Emitter
```

## Shared infrastructure

### `GeneratorSymbolAnalysis`

Owns event discovery and accessibility rules. Entry-point generators provide only their boundary policy, such as stopping at an already annotated base type or another assembly-targeted type.

### `EventShapeClassifier`

Classifies the delegate behind an event once. Emitters no longer independently decide whether an event is standard, typed, custom, ref-like, or otherwise unsupported.

### `GeneratorTypeSystem`

Owns source-type rendering, nested generic type-parameter remapping, generic constraints, and identifier escaping. The occurrence path retains its historical nullable-aware rendering through the same shared implementation.

### `EventGenerationModel`

Provides the normalized event representation consumed by emitters. Generator entry points no longer maintain separate `EventGenerationInfo`, `EventInfo`, or adapter classification structures.

### Emitters

- `EventWaitEmitter` emits one-shot wait APIs for standard and custom delegates.
- `EventStreamEmitter` emits async-stream APIs for standard and custom delegates.
- `EventOccurrenceEmitter` emits sender-aware wait and stream APIs.

The entry-point generators are responsible for target selection, diagnostics, extension-class framing, and choosing which normalized events belong to an emitter.

## Behavioral contract

This refactor is intended to preserve the generated public API and runtime behavior. Regression coverage specifically locks:

- standard, custom, and unsupported delegate classification;
- nested generic type rendering and generic constraints;
- occurrence nullability;
- keyword event identifiers;
- inherited event hiding;
- annotated-base generation boundaries;
- existing external-target and accessibility behavior.

New event-shape support should first be expressed in shared classification/modeling and only then add emitter-specific behavior when the generated API genuinely differs.

## Remaining 0.4 work

The modern generator pipeline is now structurally consolidated, and cleanup-exception semantics are defined separately in `docs/0.4-cleanup-semantics.md`. Follow-up 0.4 work should focus on stream buffering semantics, subscriber-exception policy, broader behavioral compatibility locks, and deciding how much of the Unity-specific generator can safely reuse this architecture without compromising Unity compiler/runtime compatibility.
